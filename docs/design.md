# Codex 5e DM：单人冒险 Skill 设计规格

版本：设计稿 1（2026-10-13）

## 1. 目标与边界

制作一个安装在 Codex 中的中文 Skill，让一名玩家以 D&D 5e 的方式持续游玩原创战役。玩家在 Codex 的正常聊天界面声明行动；Codex 担任地下城主（DM），负责呈现场景、扮演 NPC、理解玩家行动和作出需要判断的裁定。本地脚本负责掷骰、数值计算、回合状态和存档校验。Codex 旁边的浏览器面板打开原创 HTML 冒险界面，实时展示角色、探索地图、场景与骰子结果。玩家可以查看每次重要裁定的骰值、加值、结果与规则依据。

规则基线固定为 **2014 版 SRD 5.1**。这里的“正宗体验”指遵循该版本的角色创建、探索、社交、检定、战斗、施法、休息、成长和死亡规则，以及玩家决定自己角色行动的桌游原则。SRD 未收录的官方书籍、世界设定和模组不随产品提供。成品应明确为非官方、兼容第五版的作品，并按 [SRD 5.1 的 CC BY 4.0 文本](https://media.dndbeyond.com/compendium-images/srd/5.1/SRD_CC_v5.1.pdf)提供规定的署名。规则版本不在同一战役中混用。

当前开发阶段只交付单人冒险。玩家自定义扩展包列为后续独立阶段：届时由玩家提交内容，AI 依规则审查，玩家选择是否把获通过的包加入某个战役。首阶段不开设扩展包创建、审核或安装入口。

## 2. 玩家体验

1. **创建战役**：玩家选定主题与氛围；Codex 生成原创起始地区、当前威胁、重要 NPC 和可行动的开局局面。玩家也可以只给一句主题，其余由 Codex补全。
2. **创建角色**：按照 SRD 5.1 选择种族、职业、属性生成方法、背景、熟练项、装备和法术。规则背景提供机械收益；个人往事可以自由写、通过几个问题生成或暂时留空，不阻碍开局。
3. **进行冒险**：玩家用自然语言声明行动。Codex 先判断能否直接成功、是否存在有意义的失败风险，以及是否需要检定、攻击或豁免；需要随机结果时调用脚本，并以结果推进世界。Codex 不替玩家说台词或决定行动。
4. **战斗**：使用文字呈现场景，内部记录战斗者位置、以 5 英尺为单位的距离、先攻顺序、生命值、状态和回合资源。每回合清楚说明当前行动者及可见局面。首阶段没有图形战棋地图。
5. **结束与继续**：关键事件和机械状态及时保存。下次加载先核对角色与世界状态，给出简短回顾，从上次停下的局面继续。

**界面分工**：聊天窗口是唯一的游戏行动输入端；侧边栏网页是只读冒险面板。网页可以切换角色卡、放大探索地图或查看记录，但不提交角色行动，也不修改战役状态。探索地图展示已发现地点、连接关系和当前位置；战斗仍以文字及精确距离处理，不提供图形战棋地图。创建或加载战役时启动本地面板，并在桌面应用支持时由 Codex 打开旁边的浏览器标签。

默认由本地脚本公开掷玩家的骰子，并展示计算；玩家可在战役设置中选择自己掷骰并输入原始点数。DM 的隐秘检定可以只公开由其造成的可观察结果。两种模式均不得补造或事后修改骰值。

## 3. 系统结构

| 部件 | 职责 | 边界 |
| --- | --- | --- |
| `SKILL.md` | 识别游玩意图，路由到创建、加载、游玩、规则查询与保存流程；声明 DM 的核心原则 | 保持简短，不承载完整规则书 |
| `references/` | 按需加载建卡、一般裁定、战斗、施法、存档等操作说明；给出何时调用脚本及异常处理方法 | 只写 Codex 需要遵循的流程，不重复大段 SRD 正文 |
| `scripts/dice.py` | 骰式解析、优势/劣势、掷骰、原始结果和修正值输出 | 唯一的程序化随机数入口 |
| `scripts/character.py` | 属性、熟练加值、生命值、法术位、升级等可确定的角色计算与校验 | 不决定角色的故事或选择 |
| `scripts/combat.py` | 先攻、行动经济、命中与伤害、状态、集中、位置与回合推进 | 对规则有歧义的情境返回待裁定信息，不假装已解决 |
| `scripts/state.py` | 创建、校验、读取和原子保存战役状态；保留可恢复备份 | 仅对指定战役目录写入，不改动 Skill 安装文件 |
| `data/` | 从 SRD 5.1 整理的结构化规则索引及来源信息 | 只包含获授权或原创内容，标明规则版本 |
| `display/server.py` | 在本机回环地址提供 HTML、状态快照和实时事件流 | 只读战役数据，不承担 DM 裁定或机械计算 |
| `display/web/` | 原创 HTML、CSS 和 JavaScript 界面：角色卡、探索地图、旁白、骰子与战斗状态 | 不作为权威存档，不向 Codex 提交玩家行动 |

Skill 代码和玩家数据分开。运行时由玩家选定或确认一个战役数据根目录；其中每个战役有稳定 ID、角色与机械状态、世界事实、事件日志。结构化文件是数值状态的权威来源，Markdown 文件保存便于阅读的世界资料与回顾。加载时只读取当前场景需要的 NPC、地点或规则条目，避免把整本规则和全部历史塞进上下文。

每个战役的最小数据契约包括：`manifest.json`（稳定 ID、规则版本、创建时间）、`state.json`（角色属性与资源、当前位置、已发现地点及连接、战斗轮次、活跃状态、世界时间及最后应用的事件 ID）、`world.md`（地点、NPC、已确立的事实）、`events.jsonl`（按顺序追加的行动、旁白、掷骰、裁定和状态变化）。一次机械操作有唯一事件 ID；重试时先检查该 ID 是否已生效，防止重复扣除法术位、生命值或物品。保存时先持久化完整事件，再原子替换状态快照；加载时只重放日志中尚未应用的完整事件。事件日志用于追溯和恢复，当前机械数值以完成校验和必要重放后的 `state.json` 为准。面板只接收已公开的地点与事件，不读取 DM 尚未揭示的世界资料。

面板首次打开时读取完整快照，此后通过本机事件流接收变化；连接中断后重新读取快照，再续接事件。Codex 对玩家的回复与显示面板使用同一次已提交的游戏事件，防止数值或骰子结果不一致。没有浏览器面板时聊天游玩仍可正常进行；本地服务仅监听 `127.0.0.1`，不默认开放局域网访问。在不支持桌面浏览器面板的环境中，Skill 给出本地 URL 供玩家自行打开。

## 4. 规则与状态约束

- 角色数值由规则数据和脚本计算；Codex 不能凭叙述修改生命值、法术位、金币、装备或经验值。
- 一次掷骰记录用途、骰式、每颗骰子的点数、加值、总值、优势/劣势和最终裁定。重击、自然 1、死亡豁免等由适用规则分别处理，不把所有自然 20 都当作通用自动成功。
- 战斗状态记录当前轮次与行动者、移动余量、动作、附赠动作、反应、位置、临时生命值、状态与集中。规则事件成功处理后再写入持久状态。
- 单人遭遇按照一名角色的等级和资源设计，使用 SRD 的挑战与经验值参照；不暗改骰子或角色规则来保住剧情。若剧情中出现同行 NPC，其行动由 DM 控制，不冒充额外玩家角色。
- 当规则资料不足、玩家声明含糊或脚本拒绝非法操作时，Codex说明具体缺口并请求一个必要信息；不静默猜测数值。规则解释与家规保持可区分，家规仅在玩家明确接受后写入该战役。
- 存档写入采用先校验、再原子替换的流程；加载遇到损坏时不覆盖原文件，提示可恢复的上一个版本。

首阶段明确不包含 2024 版规则、多人联机、图形战棋地图、官方非 SRD 模组导入或扩展包工坊。这些功能不得以隐含依赖的形式拖慢单人 SRD 5.1 成品。

## 5. 完成标准与验证

首阶段的正式成品需要覆盖 SRD 5.1 所含的玩家角色选项、1–20 级成长、常用装备、法术与怪物资料，以及探索、社交、战斗、休息和升级所需的规则。特殊法术与情境的叙事裁定由 DM 完成，但角色资源消耗与机械结果必须进入同一状态系统。覆盖清单以 SRD 5.1 的目录为依据，逐项标记已结构化、可查询和已验证，避免用少量示例宣称“完整”。

验证分三层：

1. **规则测试**：骰式与优势/劣势、属性与熟练加值、命中与重击、豁免、状态、集中、法术位、休息、升级和死亡豁免，对照 SRD 示例及边界条件。
2. **状态测试**：创建、保存、重载、事件重复执行、异常中断、损坏文件恢复；确认一次行为不会重复扣资源或发放奖励。
3. **游玩验收**：一名新玩家从建卡开始，完成对话、探索检定、至少一次战斗、休息和升级；退出后重新加载，角色、NPC 态度、地点、未完成事件及消耗资源保持一致，并能追溯关键掷骰。
4. **界面验收**：在 Codex 桌面应用中打开侧边栏面板，聊天中一次行动后，面板的旁白、角色数值、骰子记录和已发现地点同步更新；刷新或断线重连后显示与存档一致。关闭面板不影响聊天游玩。

## 6. 开发顺序

| 里程碑 | 可验收交付 | 进入下一步的条件 |
| --- | --- | --- |
| M1：规则基线 | SRD 5.1 内容清单、授权署名方案、数据格式、核心裁定测试样例 | 清楚区分开放内容、原创内容与未收录内容 |
| M2：纵向可玩流程 | 支持 SRD 5.1 全部一级建卡选项及其一级核心游玩规则；完成原创开局、检定、战斗、保存与加载，面板展示角色卡、旁白和骰子 | 任一可创建的一级角色都能按其核心规则游玩；人类战士样例完整跑通，聊天和面板数据一致 |
| M3：规则覆盖 | 扩展到 SRD 5.1 的更高等级成长、后续法术、状态、怪物及规则查询 | 覆盖清单完成，规则与状态测试通过 |
| M4：成品验收 | 完成探索地图与视觉设计，加入安装说明、示例战役、端到端游玩测试、错误恢复和发布包 | 新用户按说明安装后能在聊天中独立游玩，在 Codex 侧边栏查看同步的冒险面板并续档 |
| 后续：扩展包工坊 | 玩家创作、AI 规则审查、玩家确认、按战役启用 | 单独设计与验收，不阻塞 M1–M4 |

M2 是开发过程中的可玩版本；M4 才是第一阶段成品。下一份实施计划只细化 M1 和 M2；M3、M4 在前一里程碑实测后再拆成实施任务，保持最终范围不变。
