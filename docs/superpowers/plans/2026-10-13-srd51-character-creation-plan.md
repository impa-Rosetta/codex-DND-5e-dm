# SRD 5.1 一级建卡实施计划

日期：2026-10-13

依据：[已确认的设计规格](../specs/2026-10-13-srd51-character-creation-design.md)、[SRD 5.1 原文](https://media.dndbeyond.com/compendium-images/srd/5.1/SRD_CC_v5.1.pdf)、[战役事件契约](../../data-contract.md)

## 目标、非目标与交付门槛

完成 2014 版 SRD 5.1 **全部一级建卡选项**的查询、选择、校验、数值计算和持久化。默认属性方法为玩家自行分配标准数组；同时支持六组 `4d6` 取最高三颗，以及规则允许的 27 点购点变体。一级以上成长、非 SRD 官方选项、玩家扩展包均不在此计划内。

“一级建卡完成”要求来源清单中的每个合法一级选项都有目录记录、至少一个针对性测试和可成功构建的路径。计划允许按任务逐步提交，但任何中间提交都必须清楚标注为部分覆盖，不得改 README 宣称全部建卡完成，更不得宣称 M2 可玩。M2 可玩另须保证**所有可创建职业**的一级核心能力能在冒险中实际使用；这部分战斗／施法运行时另按 M2 计划验收，不能被本建卡计划的完成替代。

每个任务按“先写失败测试 → 实现最小规则 → 跑定向测试 → 跑全套测试 → 更新覆盖记录 → 提交”的顺序执行。测试只注入固定随机值，不把伪随机种子用于正式战役。每个机械数字须能追溯到规则目录 ID 和 SRD 5.1 章节。

## 任务 0：冻结 SRD 一级选项清单

**文件**：新增 `docs/level1-options-inventory.md`；扩展 `skills/codex-5e-dm/data/rules-index.json`；新增 `tests/test_level1_inventory.py`。

1. 从项目指定的 SRD 5.1 PDF 而非当前 SRD 5.2 页面，逐项列出一级可选种族／亚种、职业、一级子职业或职业特性、侍僧及背景自定义、属性生成、语言、熟练、起始装备、一级可选戏法／法术。每项记录稳定 ID、原文章节、是否一级可选、对应数据文件、对应测试。官方未收录内容单独列为“非内置”，不补写官方数值。
2. 测试检查 ID 唯一、SRD 版本一致、来源非空、每个一级建卡选项都有覆盖入口；聚合项不能当作选项清单本身。新目录未齐全前，状态仍为 `indexed_only`。
3. 验证：`python -m unittest tests.test_level1_inventory -v`，再运行全套测试。

**完成条件**：后续工作有可对账的封闭选项列表；新增或遗漏一级选项会使清单检查失败。

## 任务 1：定义目录与建卡 JSON 接口

**文件**：新增 `skills/codex-5e-dm/data/character-options.json`（数据过大时拆成同目录分表）、`skills/codex-5e-dm/scripts/character.py`、`tests/test_character_catalog.py`、`tests/test_character_cli.py`。

1. 先以一个最小合法 SRD 选项测试目录加载；校验 `schema_version`、`ruleset=srd-5.1-2014`、目录版本、引用目标和选项 ID 唯一。固定脚本相对 Skill 根目录加载数据，不依赖 shell 当前目录。
2. CLI 提供 `options --context <JSON 文件>` 与 `build --input <JSON 文件>`；标准输出只写单个 UTF-8 JSON 对象，错误写标准错误并给非零退出码。`options` 返回当前合法 ID、必选数量、互斥限制及来源规则 ID；`build` 返回设计规格中的 `source_choices`、`derived`、`resources` 等字段。
3. 输入 JSON 的字节数、嵌套层数、自由文本长度设固定上限，拒绝未知机械字段。建立 `invalid_choice`、`missing_choice`、`unsupported_option`、`invalid_ability_method`、`unverified_roll`、`ruleset_mismatch` 错误码；错误包含字段路径，不输出半成品角色卡。
4. 验证：目录／CLI 定向测试、从项目根目录与其他工作目录运行的 CLI 测试、全套测试。

**完成条件**：稳定的机器接口与数据装载边界可用；此时只声明基础接口，不声明一级建卡完成。

## 任务 2：属性生成与共用公式

**文件**：扩展 `character.py` 与目录；新增 `tests/test_character_abilities.py`、`tests/test_character_common_math.py`。

1. 标准数组必须恰好把 `15,14,13,12,10,8` 分给六项属性各一次；重复、缺失或额外值报错。购点检查每项 8–15、SRD 成本表和总成本不超过 27；点购属于玩家选择的变体，默认不自动启用。
2. 共用计算包括种族加值后属性调整值 `floor((score-10)/2)`、一级熟练加值、技能／豁免加值、先攻、被动察觉及一级 HP。对极低体质修正的边界先核对 SRD 原文再写测试；不能靠 Codex 自行口算。
3. `4d6` 方法此阶段只定义角色计算器所需的“已核验六组结果”输入结构；未接入战役事件之前，CLI 不接受玩家自报的六个随机数作为正式角色来源。完整随机流程在任务 6 实现。
4. 验证：定向测试和全套测试。

**完成条件**：标准数组与购点角色的共同数值计算可信；掷属性仍明确标注未接入。

## 任务 3：种族、背景与熟练叠加

**文件**：扩展角色目录和 `character.py`；新增 `tests/test_character_races.py`、`tests/test_character_background.py`。

1. 逐条录入清单中 SRD 的一级种族／亚种收益：属性加值、体型、速度、语言、熟练、抗性、戏法或其他一级特性。需要选择目标的收益必须要求玩家明确给出合法 ID。
2. 录入侍僧背景及 SRD 允许的背景自定义方式；个人往事为可选自由文本，不生效机械奖励。重复熟练按 SRD 的同类替换规则处理，不重复加熟练加值。
3. 每个目录项至少一项针对性测试；组合测试覆盖种族加值在属性生成之后、重复熟练、额外语言和无效自定义。
4. 验证：种族／背景定向测试、清单检查与全套测试。

**完成条件**：SRD 一级种族／亚种与背景选择全部可计算；覆盖矩阵只更新已验证条目。

## 任务 4：职业一级特性与派生角色卡

**文件**：扩展角色目录和 `character.py`，必要时在 `scripts/` 建每个职责单一的一级特性处理模块；新增 `tests/test_character_classes.py`、`tests/test_character_resources.py`。

1. 逐职业录入一级生命骰、HP、豁免与技能熟练、护甲／武器／工具熟练、一级特性、必须做出的选择、特性使用次数及恢复条件。一级即需选择子职业的职业也在此处理；尚未到一级的子职业选择不得提前要求。
2. 共同角色卡给出最大与当前 HP、命中骰、熟练加值、技能与豁免、资源上限与初始值；缺少某类资源表示该角色没有该资源。具有 AC、速度或攻击修正影响的职业特性必须计入相应数值，不只存描述文字。
3. 每个职业有一份合法一级建卡测试和至少一项非法选择测试；职业特殊规则另加边界测试。逐类提交，任何职业未完成都保持清单未完成状态。
4. 验证：职业定向测试、清单检查与全套测试。

**完成条件**：SRD 收录职业的一级机械卡和选择路径均经测试；施法选择与装备细项由后续任务接入。

## 任务 5：起始装备、AC、武器与一级施法选择

**文件**：新增或扩展 `data/level1-equipment.json`、`data/level1-spells.json`；扩展计算器；新增 `tests/test_character_equipment.py`、`tests/test_character_spells.py`。

1. 将所有一级职业／种族／背景能合法获得或选择的起始装备及其互斥包录入目录，校验数量与替代项；计算携带装备、当前穿戴护甲／盾牌的 AC 和已装备武器的攻击加值。未选择穿戴状态时不暗自把背包里最优护甲当作已穿戴。
2. 将 SRD 收录、一级角色可选择的戏法和一级法术按职业列表与选择数量录入。区别已知、准备、法术书、仪式与法术位；只在相应职业／一级特性允许时提供选项。派生卡输出施法属性、攻击加值、豁免 DC、可用法术位与来源规则 ID。
3. 测试合法和非法装备组合、盾牌与护甲熟练、施法职业选择数量、跨职业非法法术、缺失 SRD 内容和非施法职业的空资源语义。
4. 验证：装备／施法定向测试、清单检查与全套测试。

**完成条件**：所有可建职业都能形成机械上完整的一级角色卡；此时还没有完成持久化与掷属性审计，不宣称建卡全流程完成。

## 任务 6：可信掷属性、确认与事件提交

**文件**：扩展 `scripts/dice.py` 的可审计结果消费方式；新增或扩展 `scripts/state.py`；新增 `tests/test_character_rolled_scores.py`、`tests/test_character_commit.py`、`tests/test_state_recovery.py`。

1. 战役服务先按 `operation_id` 查已有结果，再用 `dice.py` 生成六组 `4d6`。每组四颗原值、最低点舍弃项、保留三颗与合计均保存于**一个** `character.ability_scores_rolled` 事件；相同操作重试返回原事件，不重掷。平点舍弃选择固定索引并留痕。
2. 玩家把六个已掷合计分配给属性时，服务核对事件 ID、战役 ID、六组来源和一次性使用约束；外部 JSON 自报数值不能跳过验证。标准数组和购点不需要随机事件。
3. 角色预览不写 `character.created`。玩家确认后按 M1 事件契约一次提交 `character.created`，包含选择、目录版本、随机事件引用、派生卡与公开摘要，并更新 `state.json.character`。重复提交原 `operation_id` 返回同一角色和事件 ID。
4. 验证未完成事件、损坏日志、快照落后、目录版本不一致和失败重试；恢复后不改变 HP、资源或骰值。先完成测试再连聊天工作流。

**完成条件**：三种属性方式都能生成可追溯、可恢复且不会因重试重掷的一级角色。

## 任务 7：Codex 建卡流程与验收

**文件**：`skills/codex-5e-dm/SKILL.md` 与 `references/create-character.md`（在 Codex Skill 集成任务中建立）；README、覆盖矩阵与必要的端到端测试。

1. 聊天按 `options` 返回的合法列表逐步询问，不默认替玩家选择职业、种族或法术；玩家可自己写、协作生成或跳过个人往事。预览清楚区分已确认与待确认数值，显示 SRD 依据。
2. 以人类战士＋侍僧和至少一名一级施法者执行完整流程：查询选项 → 选择属性方法 → 完成所有必选项 → 预览 → 确认 → 重新加载。再逐项对账任务 0 清单，所有已支持角色的创建输出都可解析且无未声明资源。
3. README 列出实际已实现的 SRD 一级覆盖、尚未实现的游玩能力、运行方式与版本边界；只有清单全绿才写“一级建卡完成”。侧栏角色卡的公开投影与已提交事件保持同一 ID，面板实现不反向修改角色。
4. 最终运行 `python -m unittest discover -s tests -v`、`python -m json.tool` 校验所有 JSON、`git diff --check`，并检查所有机械目录项有来源与测试。

**完成条件**：新 Codex 会话可按 SRD 5.1 完成任意合法一级建卡、退出后续档并得到相同机械角色卡。M2 的完整冒险可玩声明仍须通过战斗、施法、场景和面板的独立验收。

## 顺序、风险与暂停条件

任务 0 → 1 → 2 → 3 → 4 → 5 → 6 → 7。种族与职业的数据录入可按条目分批提交，但每批都运行相同测试门槛。若规则数据形式无法表达某项一级能力，只为该稳定规则 ID 加专用处理并测试，不扩展成通用表达式执行器。若发现 SRD 原文没有某选项，停止录入、修正清单并说明；不从非 SRD 官方资料补洞。若事件格式不能承载掷属性记录或施法资源，先修订事件契约和迁移策略，再继续写存档。
