# 规则与架构决定

本文件记录会影响规则结果、存档兼容性或玩家预期的决定。更改已开始的战役时，不得静默覆盖这些决定。

| 编号 | 决定 | 原因 |
| --- | --- | --- |
| D-001 | 每个战役固定 `srd-5.1-2014`，不混用 2024 / SRD 5.2 规则。 | 同名规则在不同版本中可能有不同数值或措辞。 |
| D-002 | 规则解释优先顺序：SRD 5.1 原文 → 玩家明确接受并记录在该战役中的家规 → DM 对开放情境的裁定。 | 防止叙事便利悄悄变更机械规则；SRD 未给出明确答案的情境仍允许 DM 裁定。 |
| D-003 | 不把非 SRD 的官方内容补成“默认规则”。查询缺项时说明当前内置规则数据不含此项，并可讨论原创替代方案，但不能虚构其官方数值。 | 尊重内容边界并保持可追溯性。 |
| D-004 | 脚本是骰值、资源和机械状态的唯一权威；Codex 负责叙事与开放情境解释。 | 防止故事文本与角色卡出现两套数值。 |
| D-005 | 单次机械结算为一个已提交事件，内部可同时记录骰值、伤害、状态变化和公开反馈；操作重试复用 `operation_id`。 | 断线、超时和重复调用不能造成二次扣血或重掷。 |
| D-006 | 地图只公开已发现地点与连接；面板只读，玩家行动只在 Codex 聊天中输入。 | 保持探索悬念和唯一行动入口。 |
| D-007 | M2 的纵向样例是 1 级人类战士、侍僧背景、SRD 装备、哥布林与原创开局。M2 不是完整规则覆盖或正式成品。 | 用可验证的窄范围打通体验，再扩展到 M3/M4。 |
| D-008 | Python 标准库是 M2 脚本与本地服务的运行基线，网页服务默认仅绑定 `127.0.0.1`。 | 降低安装门槛，并避免默认对局域网暴露战役数据。 |
| D-009 | 玩家个人经历可自写、由 DM 引导生成或暂时留空；背景带来的机械收益依 SRD 数据处理。 | 自由故事不应阻碍按规则建卡。 |

## 家规记录格式

家规是**战役级显式变更**，至少记录 `house_rule_id`、原 SRD 规则 ID、变更文本、玩家接受时间、适用范围和生效事件 ID。DM 先说明将改变的机械结果，再由玩家明确同意；未同意的提议不能写入状态。家规不会修改共享的 SRD 索引，也不会影响其他战役。
